# 三行歌词兼容性

启动器按 DLL SHA-256 选择 `compatibility_profiles.json` 中的适配配置，检查 x64 PE 和函数指纹，再在注入进程内核对函数机器码。地址不再写死在绘制脚本中。

目前经过验证的配置为网易云音乐 3.1.41 x64 Build 205529，以及 3.1.42 x64 Build 205594、Patch 14827e8。多配置框架不代表其他版本已经可用。

未知版本会只读扫描已知函数特征，保存 `compatibility-report.json` 并拒绝注入。唯一候选也不能证明数据结构、调用约定或渲染流程相同，不能自动晋升为受支持版本。

适配新版本时，应重新核对函数边界、生产者向量、行结构、时间与持续时长、字体调用参数和渲染范围，逐帧验证歌曲对齐后再添加独立配置。不能只修改 SHA-256 或复制旧地址。

只读检查：`launcher.py --app-dir <客户端目录> --check-only`。这不会启动客户端或安装 hook。

测试覆盖当前指纹通过、未知指纹拒绝、函数指纹异常拒绝和无效文件拒绝。现场注入通过仍不代表每首歌三行同句，需要实际歌曲验证。

## 3.1.42 适配记录（2026-10-21）

- DLL SHA-256：`557d7706dedc8556a8bd279d4dfe2bc05b80ad729a8749caccd9e29916935493`。
- 重新读取 PE 异常表中的函数边界，并逐条对比四个入口及其直接调用的函数。忽略重定位后的分支目标和 RIP 相对位移后，37 个函数的指令结构一致；内存字段偏移、常量、调用参数和入口位置另行保留核对。
- 新 RVA：`vectorOf=0x11302b0`、`fontHook=0x110ad1b`、`selectLine=0x111a6a0`，渲染范围 `[0x1122dc0, 0x11232af)`。字体 hook 仍在 `xmm2` 已写入 `[rsp+0x18]` 之后。
- 实机只读核对 producer `+0x10/+0x18`、parser/manager 链、64 字节行结构、UTF-16 字符串和时间/持续时长。匿名回归样本中原文、中文和罗马音行数不同，不能按下标等长配对。
- 实测桌面辅助向量与罗马音解析器共享行内存。先校正辅助时间、后配对文本，会把 40490ms 的罗马音临时移到 43160ms，导致它与仍为 40490ms 的中文超出配对阈值，44 秒附近漏中文。现在先按原始时间生成文本配对，再在选行期间校正辅助 start/duration，函数返回时恢复。
- 历史实机检查覆盖三行同句、辅助向量与解析器共享内存、换歌和拖动进度。公开文档不保留个人曲目和播放采样；模拟测试继续回归对应的边界条件。
- 首次诊断中探针和候选校验重叠附加后，客户端退出过一次；后续改为串行加载、卸载，未再复现。正式安装只保留一个歌词 helper。
- 工具箱优先加载自己的 `NcmToolbox/Lyric3`，独立启动入口加载客户端旁的 `Lyric3`。两处必须安装同一组源码；便携打包脚本现在直接取 `desktop-lyrics` 的受维护源码，避免重新带入过期暂存文件。

`node --test desktop-lyrics/test_triline.mjs` 使用完整绘制脚本和模拟内存，回归共享/独立向量的文本配对、帧内时间校正和返回恢复。该测试不代替实机验收。其他缺行和特殊时间戳仍需按实际数据诊断。
